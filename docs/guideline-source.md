# DIT Thesis Guideline - quick reference

Summary of `leitfaden_abschlussarbeiten_en.pdf` (Deggendorf Institute
of Technology, "Thesis Guideline", Version 1.0, 27.06.2023), for
reference without re-opening the original PDF. **The original PDF is
the authoritative source** - if anything here seems to conflict with
it, or with something your supervisor tells you directly, trust the
PDF / your supervisor over this summary.

## Page count
- Bachelor: ~50 text pages. Master: ~80 text pages. ±10% tolerance.
- Excludes table of contents, bibliography, formula directories,
  appendix.
- Quality doesn't scale with page count - guideline explicitly warns
  against long-winded padding.

## Layout
| Aspect | Requirement |
|---|---|
| Paper | DIN A4, single-sided |
| Font size | 11-12pt body, 14pt chapter headings |
| Font colour | Black |
| Margins | top 2.5cm, bottom 2.5cm, left 3cm, right 2cm |
| Line spacing | 1.5 |
| Header/footer | Consecutive page numbers |
| Alignment | Justified, automatic hyphenation |
| Structure | 1, 1.1, 1.2, 2, 2.1, 2.1.1 ... no trailing dot on the final level |

## Linguistic style
- No first person ever; use passive voice.
- Avoid convoluted subordinate clauses; use active statement clauses.
- Never start a sentence with a conjunction.
- Avoid oral-language abbreviations, redundant filler words, vague
  hedging ("this chapter is meant to demonstrate..." -> "this chapter
  demonstrates...").
- Avoid unspecific terms ("synergy", "process", "system") and
  meta-references ("as already shown in illustration 3").
- Headings: no source/abbreviation/punctuation, not underlined or
  indented, one line, bold, capitalised, same font as body.
- No personal opinions/conclusions or exaggeration.

## Orthography
- Numbers >12 as numerals in running text; <12 spelled out (except
  physical quantities).
- Space between numerical value and unit in English (`230 V`, not
  German-style hyphenation).
- `e.g.`, `etc.`, `i.e.` - space between the two parts.
- No space just inside brackets.

## Figures/tables
- Tables get titles; figures get captions.
- Original/vector quality where possible; not framed; kept within
  page margins; divide text between paragraphs (not stacked on one
  page except long result sections).
- **No university logo anywhere. No company emblem anywhere either.**

## Formulas/units
- Recognised symbols (e.g. `I` for current), explained on first use.
- Sentence-ending dot goes on top of a trailing equation, no colon
  introducing it in that case.
- Space between numerical value and unit; decimal separator is a dot
  in English-language theses (comma in German).
- Units/constants (`e`, `i`, `j`) and differential `d` are not
  italicised.
- Multiplication: `·`, never `x` or `*` or a plain dot.
- Formulas left-justified or centred; if numbered, the number sits
  right-justified at the margin.

## Content structure (chapter 4 of the guideline)
1. **Title page** - key info, NO page number, NO university logo.
2. **Restriction note / NDA** - only if a company requires it; DIT
   doesn't support this process.
3. **Acknowledgement** - optional.
4. **Statement of Authorship** - signed, no page number.
5. **Index of Abbreviations** - alphabetical, technical abbreviations
   only (not common ones like "etc."), spelled out in full + bracketed
   on first use in the text too.
6. **Abstract** - optional, 120-150 words, with key words.
7. **Introduction** (1-3pp guideline recommendation): historical
   reference/relevance/central-concept definition, ACTUAL vs.
   TARGET state, fundamental goal, state of the art, open questions,
   methodological approach used, pros/cons of the approach, relation
   to the table of contents.
8. **Groundwork/Fundamental Principles** (8-16pp): background needed
   to understand the methodology; existing empirical results; prior
   approaches by other authors.
9. **Methodology** (2-4 chapters, 10-20pp each): the core, own-work
   chapter(s). Separate chapters per sub-problem if useful. Describe
   the solution completely/gaplessly. Practical thesis -> describe
   devices/accuracy/test setups. Theoretical thesis -> describe
   models/simulations/requirements. Justify design choices (why A
   over B).
10. **Results** (4-12pp): present and explain results (not yet
    evaluate/discuss). Comprehensiveness of testing, explain
    deviations/inaccuracies, applicability of results elsewhere.
11. **Summary & Prospects** (1-3pp): succinct summary, answer the
    introduction's questions precisely, critical reflection (what
    worked/what could be better), outlook/open questions - no new
    trains of thought introduced here.
12. **Bibliography**: DIN-norm citation, numbered by citation order or
    alphabetically sorted, `[1]`-style in-text brackets, always date
    web sources were accessed. Avoid plagiarism; reliable sources =
    technical literature, journal articles, reputable web sources.
13. **Appendix**: separate title page from the rest of the thesis;
    subdivided/numbered (A1, A1.1, A1.2, A2...) if large; programming
    code goes on the electronic data carrier, not printed in full.
